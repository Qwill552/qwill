# LiveKit — нагрузочная проверка

Рунбук шага ЗВОНКИ-12 (пункт 5): сколько запаса у SFU в Дубае для группового звонка.
Выполняется на самой машине с LiveKit — `livekit-cli` тянет трафик напрямую в контейнер
через `wss://livekit.qwill.mooo.com`, гонять его с дев-машины бессмысленно (сеть и задержка
другие).

## Предпосылки

- LiveKit поднят и отвечает (`infra/livekit/README.md`, шаг 7 — `curl` возвращает `OK`).
- `LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET` — те же, что в `/opt/livekit/.env`.
- Docker на машине уже стоит (`deploy.md`).
- Открыт второй терминал на той же машине для `docker stats` во время прогона.

## Перед первым прогоном

Флаги `load-test` отличаются между версиями `livekit-cli`/`lk`. Проверить актуальный набор
перед тем, как полагаться на команды ниже:

```bash
docker run --rm livekit/livekit-cli load-test --help
```

Команды ниже собраны под вариант с `--publishers` (все публикующие шлют и аудио, и видео) и
`--audio-publishers`/`--video-publishers` (публикующие делятся по типу трека). Если у
установленной версии другие имена флагов — поправить здесь же, чтобы файл оставался точным
для следующего прогона.

## Прогон 1 — видео

```bash
docker run --rm livekit/livekit-cli load-test \
  --url wss://livekit.qwill.mooo.com \
  --api-key <ключ> --api-secret <секрет> \
  --room loadtest --publishers 5 --subscribers 20 --duration 2m
```

Во втором терминале, синхронно с прогоном:

```bash
docker stats --no-stream livekit
```

(снять 2-3 замера за 2 минуты прогона, а не один — нагрузка не постоянна всё время теста).

## Прогон 2 — только аудио

```bash
docker run --rm livekit/livekit-cli load-test \
  --url wss://livekit.qwill.mooo.com \
  --api-key <ключ> --api-secret <секрет> \
  --room loadtest --audio-publishers 5 --video-publishers 0 --subscribers 20 --duration 2m
```

`docker stats` — так же, как в прогоне 1.

## Ориентир

Из ТЗ шага: если 5 публикующих и 20 подписчиков с видео дают меньше 30% CPU — запас по
нагрузке для мессенджера более чем достаточный (реальные групповые звонки на порядок меньше
по числу участников, см. `calls.md`, «участников без явного лимита», переключение на ленту
с 8).
